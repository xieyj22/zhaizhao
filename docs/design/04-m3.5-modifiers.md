## 1. 设计动机

M3 meta 层把"单场决斗"扩成"闯荡残照江湖"。肉鸽的可重玩性靠 **run 间差异**驱动——每局抽 2 条
"天象/时令"modifier 改变本局规则，让同样的章 1 图打出不同体验。modifier 故意做 **轻量、叠加、可读**：

- **轻量**：每条只动 1-2 个数值 hook，不改结构（不动招式池/不动 DAG 拓扑）。
- **叠加**：2 条 roll 去重，effect 合并进 `modifier_state`，数值 hook 求和、dict hook 深合并。
- **可读**：hub 用 hook 反推中文简述（"锐金势强/煞气弥漫/独行…"），玩家一眼懂本局规则。

难度用 `difficulty` 字段（-2 测不准 ~ +2 险地频仍/+9 boss）标注，供 `EnemyPool.pick` 的 risk 偏好与未来 meta 平衡参考。

**平衡假设**：POOL 故意混入正负 difficulty（"测不准" -2 是正面 modifier，"独行" cap=1 是负面但补 max_hp），
让 roll 出的 2 条组合有时强有时弱，制造 run 间张力。`difficulty` 当前**未被 roll 使用**（roll 是均匀随机去重 2 条），
留作未来"加权 roll / 难度曲线"扩展位。

### roll / apply 语义（`run_modifier.gd:36`/`:48`）
- `roll(seed)`：seeded 从 POOL 抽 2 个去重。同 seed 同结果（确定性）。
- `apply(ids)`：合并进 `modifier_state`。
  - **数值 hook**（int/float）：求和（`state[hook] = existing + new`）。
  - **dict hook**（如 stance bonus / hazard flag）：`_deep_merge`——bool 值（hazard flag）直接置，数值（stance bonus）求和。
- `apply([])` → 空 `modifier_state`，全链路 noop（边界守护，与 M3 逐字节一致）。

## 3. hook 契约（modifier_state 的 key → 消费点）

`modifier_state: Dictionary` 是 `RunState` 第 16 字段（JSON-safe）。每个 key 对应一个消费点：

| hook 键 | 类型 | 消费点 | 行为 |
|---------|------|--------|------|
| `kit_stance_damage_bonus` | `{stance:Δ}` | `battle_builder._build_kit` / `_apply_modifier_to_tech` | 按招 resulting_stance 所属势 base_damage += Δ |
| `kit_stance_speed_bonus` | `{stance:Δ}` | 同上 | 按招 resulting_stance speed += Δ |
| `kit_feint_bonus_delta` | float | 同上（仅 FEINT 招） | `feint_bonus_mult += Δ` |
| `hazard_baseline` | `{hazard flags}` | `battle_builder.build` | 深合并进 `BattleState.hazard_modifiers`（每场都有，不限险地节点） |
| `ai_confidence_cap_delta` | float | `battle.gd._ready` tuning override | `tuning.l2_confidence_cap += Δ`（AI 玩家建模置信上限） |
| `morale_cap_delta` | int | `battle.gd._ready` tuning override | `tuning.morale_cap_turn += Δ`（战意上限→平局阈值） |
| `roster_cap` | int | `hub.gd._can_recruit` | 招募上限（「独行」=1） |
| `relation_start_delta` | int | `run_factory.apply_init_hooks` | 初始非 F8 关系 += Δ |
| `credit_mult` | float | 镖局（escort）/信用产出（M4 接） | 信用产出/消费倍率 |
| `max_hp_mult` | float | `run_factory.apply_init_hooks` | 主角（roster 全员）max_hp/hp × mult |
| `hazard_node_count_delta` | int | `run_factory.init_run`→`generate_map` | 险地节点数增量 |

**hook 命名约定**：消费点用 hook 键（不是 modifier id）——因 meta UI 展示的是「效果」而非「名字」，
避免 POOL 文案改动时 UI 失同步（见 `hub.gd._modifier_brief` 注释）。

## 4. enemy_pool（章 1 敌人组合）

源：`src/meta/enemy_pool.gd`。替换 `map.gd` 早期硬编码敌人，7 组 seeded 抽。

| id | 派 | 性格 | difficulty | affinity（节点类型） | 敌人数 |
|----|----|------|-----------|---------------------|--------|
| `chifeng_patrol` | F2 赤锋 | brute | 1 | duel/hazard | 2 |
| `pangen_elder` | F3 盘根 | brain | 1 | duel/sparring | 1（hp30） |
| `huazong_trickster` | F6 幻踪 | trick | 1 | duel/hazard | 1 |
| `tingchao_scholar` | F4 听潮 | brain | 0 | duel | 1（hp18） |
| `jianghu_ronin` | F1 镜照 | brain | 0 | sparring | 1（hp16） |
| `xueyi_scout_elite` | F8 血衣 | brute | 2 | hazard | 2（hp24） |
| `hailianzheng` | F2 赤锋 | brute | 9（boss） | boss | 1（hp40，3招） |

### pick 语义（`enemy_pool.gd:28`）
- `pick(node_type, risk, seed)`：boss 固定返回 `hailianzheng`；其余按 `affinity` 过滤候选后 seeded 抽。
- `risk > 0` 时偏好高 difficulty 候选（`difficulty >= 1`，无则全留）——险地节点风险高→偏好硬敌。
- affinity 无匹配时退回"除 boss 外全池"。
- 方法名用 `pick` 非 `get`（GDScript `Class.get()` 与 `Object.get()` 冲突，同 `TechniqueDB.find` 坑）。

**已知偏差**：`jianghu_ronin` spec 原写 kit=`tongshi_*`（通式招），但通式招在 `technique_kit` 工厂
而非 `technique_data` 表，`TechniqueDB` 不索引；改为 F1 招牌 `jingzhao_*`。这是 spec→实现的一次漂移修正。

## 5. hazard_delta（map_generator 第 3 参）

源：`src/meta/map_generator.gd` `generate_map(seed, chapter, hazard_delta=0)`。

- `hazard_delta`：险地节点数增量（「险地频仍」modifier roll +2）。init_run 在调 generate_map 前读
  `modifier_state.hazard_node_count_delta` 传入。
- `_apply_hazard_delta`：把指定数量普通节点改造成 hazard 节点。
- hazard 节点带 `reward_tier`（"normal" / "t3_chance"）——t3_chance 有几率掉 T3 隐藏招，map 渲染标 ★高回报。
- **peril path 保证**：generate_map 保证至少一条"险径"（含 hazard 的路径），让走险地策略始终可行。
- **边界守护**：`hazard_delta=0` 时与 M3 逐字节一致（160 代 stress test 守护）。

## 6. 消费链路总表（hook → 哪个文件读它）

```
init_run (run_factory.gd)
  ├─ 读 hazard_node_count_delta → generate_map(hazard_delta)        [map 生成期]
  └─ apply_init_hooks
      ├─ relation_start_delta → 非F8 派关系 += Δ                    [init 期]
      └─ max_hp_mult → roster 全员 max_hp/hp × mult                 [init 期]

battle_builder.build (battle_builder.gd)
  ├─ hazard_baseline 深合并进 hazard_modifiers                       [每场]
  └─ _build_kit 读 kit_stance_damage_bonus/speed_bonus/feint_delta  [每场，按招势注入]

battle.gd._ready (battle.gd)
  └─ ai_confidence_cap_delta / morale_cap_delta → tuning override   [每场]

hub.gd
  ├─ _modifier_brief 读全 hook 反推中文                              [UI 展示]
  └─ _can_recruit 读 roster_cap                                      [招募 gate]

map.gd
  └─ hazard 节点渲染（reward_tier ★）                                [UI 展示]

[未接，留 M4] credit_mult → 镖局信用消费 / 节点信用产出
```
